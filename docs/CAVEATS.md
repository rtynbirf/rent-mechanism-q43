## Как завести issue по caveat (процедура)

1. `python3 scripts/caveat_registry.py new --id CAV-XX` — печатает готовый шаблон тела issue (заголовок, caveat, формула приёмки, чек-боксы).
2. Создай issue в GitHub UI (или `gh issue create -t "[CAV-XX] …" -F body.md -l caveat`) и впиши номер в `results/caveat_registry.json → caveats[].issue` (ручная правка одной строки реестра).
3. `caveat_registry.py check --live` — сверка: `search is:open label:caveat` возвращает полный список, числа реестра и GitHub сходятся.
4. Закрытие caveat — по формуле приёмки записи; реестр обновляется (`--build` не трогает issue/state — они ведутся руками), коммит + PATCH issue.

Скрипт НЕ создаёт issues сам: в репо нет API-скрипта создания issues — по правилу Волны ×4 процедура документируется, автосоздание не имитируется.

## Приёмка (машинная, из issue)

- каждый caveat имеет формулу приёмки — колонка «Формула приёмки» (проверяется `check`);
- `search is:open label:caveat` — сверка живым API: `caveat_registry.py check --live`;
- числа сходятся: счётчики реестра == таблице == README-статусу.
